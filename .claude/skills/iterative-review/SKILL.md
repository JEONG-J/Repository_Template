# Iterative Review Skill

Claude가 코드를 작성하고, Codex가 리뷰하고, Claude가 수정하는 사이클을 **총 5라운드** 반복하여 코드 품질을 점진적으로 개선합니다.

## 전체 흐름

```
[1단계] Claude → 초기 코드 작성
[2단계] Codex → Round 1 리뷰
[3단계] Claude → Round 1 수정
[4단계] Codex → Round 2 리뷰
[5단계] Claude → Round 2 수정
...
[N단계] Codex → Round 5 최종 리뷰 → 완료
```

---

## 진행 상황 표

**매 라운드의 리뷰 완료 시점과 수정 완료 시점에 반드시 아래 형식의 진행 상황 표를 출력합니다.**
표는 누적 방식으로, 진행된 라운드까지의 정보를 모두 포함합니다.

### 리뷰 완료 후 출력 형식

```
📋 현재까지 상황:

| 라운드 | Codex 지적 | 수정 | 결과 |
|--------|-----------|------|------|
| 1차 | 4개 HIGH | 전부 수정 | → 2차 리뷰 |
| 2차 | 5개 (1 컴파일에러 포함) | 전부 수정 | → 3차 리뷰 |
| 3차 | 5개 | 전부 수정 | → 4차 리뷰 |
| 4차 | 4개 | 전부 수정 | → 5차 리뷰 대기 중 |
```

### 표 컬럼 규칙

- **라운드**: `1차`, `2차`, ... `5차`
- **Codex 지적**: 심각도별 개수 요약 (예: `3개 HIGH, 2개 MED`, `4개 HIGH`, `5개 (1 컴파일에러 포함)`)
- **수정**: `전부 수정`, `N개 수정 / M개 스킵`, 또는 현재 라운드면 `수정 중...`
- **결과**: 완료된 라운드는 `→ N+1차 리뷰`, 현재 라운드는 `→ N+1차 리뷰 대기 중`, 마지막 라운드는 `✅ 완료`

### 출력 타이밍

1. **리뷰 완료 직후** (🔍 출력 다음): 해당 라운드의 "수정" 칸은 비워두거나 `수정 중...`
2. **수정 완료 직후** (🔧 출력 다음): 해당 라운드의 "수정" 칸 채우고 "결과" 칸 업데이트

## 작업 절차

### Step 0. 작업 준비

인자로 받은 `{작업 설명}`을 파악합니다. 인자가 없으면 사용자에게 무엇을 만들지 질문합니다.

현재 브랜치와 관련 파일을 확인합니다:
```bash
git status
git branch --show-current
```

---

### Step 1. 초기 코드 작성 (Claude)

`{작업 설명}`에 따라 코드를 작성합니다.

**CLAUDE.md 규칙 준수:**
- `@Observable` ViewModel 패턴
- Clean Architecture (View → ViewModel → UseCase → Repository)
- `Loadable<T>` 비동기 상태 관리
- `private` 접근 제어자 적극 활용
- `fileprivate enum Constants` 상수 분리
- 들여쓰기 4 spaces, 최대 99자

작성 완료 후 출력:
```
✏️ [초기 코드 작성 완료]
작성된 파일:
- {파일 경로 1}
- {파일 경로 2}
```

---

### Step 2–11. 리뷰-수정 루프 (5라운드)

아래 A → B 사이클을 **Round 1부터 Round 5까지** 반복합니다.

#### A. Codex 리뷰 요청

변경된 파일들의 전체 내용을 수집한 뒤 Codex에게 리뷰를 요청합니다:

```bash
# 변경된 swift 파일 목록 수집
CHANGED_FILES=$(git diff --name-only HEAD 2>/dev/null || git status --short | awk '{print $2}' | grep "\.swift$")

# 각 파일 내용을 하나의 문자열로 합치기
CODE_CONTENT=""
for f in $CHANGED_FILES; do
  CODE_CONTENT="$CODE_CONTENT
=== $f ===
$(cat $f)
"
done

# Codex에게 리뷰 요청 (비대화형 모드) - 결과를 파일에 저장
codex exec --full-auto "
당신은 iOS SwiftUI 전문 코드 리뷰어입니다.
아래 코드를 리뷰하고 **구체적인 개선사항**을 항목별로 제시하세요.

리뷰 관점:
1. Swift/SwiftUI 모범 사례 준수 여부
2. SOLID 원칙 위반 여부
3. @Observable 패턴 올바른 사용
4. 성능 문제 (불필요한 뷰 갱신, 메모리 누수 등)
5. 에러 처리 누락 또는 부적절한 처리
6. 가독성 및 유지보수성
7. 보안 취약점

응답 형식:
[심각도: 높음/중간/낮음] 파일명:줄번호 - 문제 설명 및 수정 방법

--- 리뷰 대상 코드 ---
$CODE_CONTENT
" -o /tmp/codex_review_round{N}.txt 2>&1 | tee /tmp/codex_review_round{N}.txt

리뷰 완료 후 출력:
```
🔍 [Round {N} - Codex 리뷰 완료]
발견된 이슈:
{리뷰 결과 요약}

📋 현재까지 상황:

| 라운드 | Codex 지적 | 수정 | 결과 |
|--------|-----------|------|------|
| ... (누적된 이전 라운드 정보) ... |
| {N}차 | {심각도별 개수} | 수정 중... | |
```

#### B. Claude 수정 적용

Codex 리뷰 결과를 바탕으로 코드를 수정합니다.

**수정 우선순위:**
1. 심각도 높음 → 반드시 수정
2. 심각도 중간 → 맥락에 따라 수정 (수정 이유 명시)
3. 심각도 낮음 → 선택적 수정 (CLAUDE.md 원칙과 상충 시 무시 가능)

**수정하지 않는 경우 명시:**
- Codex 제안이 CLAUDE.md 원칙과 상충하는 경우
- 이미 의도된 설계인 경우
- 프로젝트 컨벤션과 다른 경우

수정 완료 후 출력:
```
🔧 [Round {N} - 수정 완료]
수정 사항:
- ✅ {수정한 내용}
- ⏭️ {수정하지 않은 내용} → 이유: {이유}

📋 현재까지 상황:

| 라운드 | Codex 지적 | 수정 | 결과 |
|--------|-----------|------|------|
| ... (누적된 이전 라운드 정보) ... |
| {N}차 | {심각도별 개수} | {수정 상태} | → {N+1}차 리뷰 |
```

## Codex 미설치 시 대체 방법

`codex` CLI가 없거나 `exec` 서브커맨드를 지원하지 않는 구버전인 경우, Claude 자신이 Codex 역할을 수행합니다:
- **리뷰어 페르소나**: "나는 이 코드를 처음 보는 시니어 iOS 개발자다"라는 관점에서 리뷰
- 동일한 리뷰 관점(7가지) 적용
- 동일한 출력 형식 사용

```bash
# Codex 설치 및 버전 확인 (exec 서브커맨드 지원 여부)
if ! command -v codex &> /dev/null; then
  echo "⚠️ codex CLI가 없습니다. Claude가 리뷰어 역할을 대신합니다."
elif ! codex exec --help &> /dev/null; then
  echo "⚠️ codex CLI가 구버전입니다 (exec 서브커맨드 미지원). Claude가 리뷰어 역할을 대신합니다."
  echo "   최신 버전으로 업그레이드: npm install -g @openai/codex"
fi
```

## 주의사항

- **코드 작성 전 반드시 관련 파일 Read** → 기존 코드 파악 후 작성
- **매 라운드 수정 후 빌드 에러 없는지 확인** (가능한 경우)
- **Round 5 이후 추가 수정이 필요하면 사용자에게 알림**
- **CLAUDE.md의 아키텍처 원칙은 Codex 리뷰보다 우선**
